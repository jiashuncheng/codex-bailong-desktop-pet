# 补丁发布

程序补丁与动画补丁共用 GitHub 稳定版序列；单独发布按改动性质递增，同时发布共用同一版本。名称为“程序补丁包 1.0.1”“动画补丁包 1.0.2”，同批两包均为 1.0.3。采用 SemVer：修复优化递增修订号，兼容新功能递增次版本号，不兼容改动递增主版本号；各段不限位数，不按十进制自动进位。本地开发编号独立。

## 程序补丁

发布 program.zip、program.json 与 SHA256SUMS.txt；底层文件名继续使用 bailong-desktop-pet-VERSION-program.*，使用 Release 标题和附件 label 展示人类可读名称。程序补丁是累计程序包，复用匹配的本地动画，包含所有程序/运行库/字体。用户只需最新一份程序补丁，不逐个重放旧程序补丁。程序和动画按缺失类型分别更新。完整安装基包不必随每次逻辑变更重新上传，首次安装入口须固定指向仍提供安装器的 Release。不能把 program.zip 当作首次安装器。

## 动画补丁

先校验轻量与高清源，然后显式运行：

```powershell
python build_animation_update.py --catalog app/material_catalog.json --light-source build/materials/light --hd-source <已验证高清目录> --destination <本轮发布暂存目录> --version <公开版本> --minimum-program-version <支持该动画的最低已公开程序版本>
```

生成 animation.json、animation-light.zip、animation-hd.zip、SHA256SUMS.txt，以及给同批程序构建使用的 animation-catalog-VERSION.json。完整校验所有附件后再公开。运行此工具是明确的发布构建动作，普通本地迭代不运行它。

描述文件绑定公开版本、最低程序版本、两档内容 ID、每个文件 SHA-256、每个 ZIP 的大小与 SHA-256，以及本项目精确的版本下载地址。客户端先校验描述，再按当前画质只下载一档；仅卡片用户不下载动画，也不显示人物。素材先写入新的内容目录，后台校验文件和播放入口后等动作结束才原子切换目录指针。失败或取消保留当前目录。素材设置可回退上一套；较新的程序补丁保留独立动画覆盖，只有程序携带更新的动画目录时才替代它。回退动画不降低程序版本号。

GitHub API 限流或拒绝时，程序和动画补丁都可通过本仓库 latest/download/SHA256SUMS.txt 核验发现，不要求本轮同时有完整包。

## 同批发布

先生成动画目录，在独立发布源副本中将 app/material_catalog.json 换成该目录，再构建同版本程序包；两个打包入口都会拒绝目录不一致的组合。客户端先暂存所需动画，再启动程序升级；不会在旧程序仍运行时提交新目录。只建一个稳定 Release，两个补丁共用公开版本。

## 旧客户端与首次安装

v1.0.0 不能识别独立动画稳定版。v1.0.1 程序补丁已交付新版更新器，动画补丁的 minimumProgramVersion 不得低于该公开程序版。未安装这次程序升级的旧客户端需要明确的程序升级/安装基包链接；不能通过只改附件名称赋予旧客户端新协议。独立动画内容 ID 仍是校验标识，不另占公开序号。旧 materials-ID 资源 Release 继续服务已有目录，不占稳定版本号。

v1.0.1 同时提供不含动画的程序补丁安装器，作为首次安装及手动升级入口。兼容旧更新器的 windows-x64.zip 文件名保留，实际载荷只有程序，不是含动画完整包。

首个支持独立动画协议的公开程序版须同步更新一次安装基包，并把 README 的固定安装入口改到该基包。否则未来 Latest 变成纯动画补丁后，新用户仍安装不识别新协议的旧基包，会无法完成更新。之后例行逻辑更新再只发程序补丁。旧客户端没有新协议，不能靠换附件名修补；该迁移门禁必须在正式发布前落实。

## 公开内容核对

发布前检查 README、快速部署、平台说明、候选功能状态和动图引用。正式入口始终指向已公开可用的版本；先发布并未登录验证附件可用，再更新首页版本与下载链接。发现旧说明不符时同步修正，历史记录标明适用版本。

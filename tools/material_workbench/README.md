# 白龙素材工作台

<img src="icons/bailong-editor-preview.png" width="112" alt="白龙素材编辑器：白龙头像与胶片剪刀" />

PySide6 / Qt 桌面工具：扫描新增视频 → 在界面检查原片和处理结果 → 拖动、滚轮或数值调整 → 生成 → 加入桌宠。处理算法、界面和加载事务一起维护；无需改当前桌宠的大小和位置。

Windows 可在仓库根目录运行 `创建素材编辑器桌面图标.cmd`，或用当前环境运行 `python tools/material_workbench/install_shortcut.py`。桌面入口名为“白龙素材编辑器”，使用白龙头像加紫色胶片剪刀标记，直接启动工作台；重复执行会更新同一个编辑器快捷方式，不覆盖其他同名程序。图标包含16至256像素多尺寸ICO、PNG和可编辑SVG；角色来源遵循仓库 `NOTICE.md`。macOS继续使用 `素材工作台.command`，桌面链接安装入口仅适用于Windows。

## 安装与启动

先按仓库首页准备桌宠源码环境及原白龙高清素材。工作台复用仓库 `.venv`，不会把其他电脑的 Python 路径写死在启动脚本里。

1. 双击仓库根目录的 `安装素材工作台依赖.cmd`（Windows）或 `安装素材工作台依赖.command`（macOS）。这会安装工作台依赖和绿幕处理依赖，并下载约 4.6 MB 的 U²-Net 小模型，校验固定大小与 SHA-256。
2. 双击 `素材工作台.cmd` 或 `素材工作台.command`。
3. 选择新增素材目录。已有纯透明 WebM/WebP 会保留原透明度；绿底视频使用原分辨率抠图。16:9、4:3 横版与 3:4 竖版均可输入。
4. 在原片/处理结果之间查看，生成后确认，再点界面的加入桌宠按钮。勾选自动加入仅在你希望处理完立即应用时使用。

如果只处理透明素材，可以省略模型和 ONNX 依赖，在仓库根目录使用当前环境的 Python 执行：

```sh
python -m pip install -r requirements-source.txt -r tools/material_workbench/requirements-workbench.txt
python tools/material_workbench/启动.py
```

绿幕处理的手动安装命令：

```sh
python -m pip install -r tools/material_workbench/requirements-matting.txt
python tools/material_workbench/download_models.py
```

macOS 如缺执行权限，可在仓库根目录运行 `chmod +x *.command`。Windows 已完成本机验证；macOS 的路径、锁和启动代码已兼容，仍需 Mac 实机检验显示、编解码与桌宠重启。

## 预览和手动校准

- 支持播放、暂停、定位、循环和速度调整。鼠标拖动人物改位置，滚轮调整大小，Shift 配合滚轮做更细调整，也能输入数值。
- 标准白龙、标准脚底和面板/胶囊提供固定参照；说明文字在预览外，调整中的人物不绘制额外晃动的框。
- “适应窗口”只便于看完整动作；“桌宠实际尺寸”按桌宠设置与逻辑像素预览。系统 DPI、屏幕缩放和窗口可用空间仍影响物理观感。
- 正在显示的面板优先读运行记录；未显示的面板按源码布局估算，界面会区分两者。仅预览不会更新桌宠。
- 手动修改会纳入重新生成和缓存判断；同一段动画内使用固定缩放与偏移，保持动作原来的起伏，避免逐帧变大变小。

## 裁剪与拼接

选中素材，在预览旁点“裁剪 / 拼接”。当前查看原片时剪原片；当前查看处理后时剪已处理的透明素材。需要拼接的几段建议先统一人物大小与脚底，再用处理后版本剪辑。

1. 拖动进度条找画面，点“当前帧设为起点 / 终点”，也可直接填写秒数，精确到毫秒。起点包含当前帧开头，终点包含当前帧结束；原片预览仍显示完整视频。
2. 点“添加片段”加入其他视频，拖动左侧列表改变顺序。“复制”可选同一视频的另一段；“重复次数”可延长一个选段。
3. 在“导出档位”中多选：高清 Q95、均衡 Q90、小体积 Q85、逐像素无损。点“生成对比预览”，通过预览上方的档位菜单切换，菜单显示每档实际文件大小。颜色压缩档保留完整透明通道；无损档保留输入像素。所有档位保持分辨率和逐帧时长。
4. 满意后保存当前档位，也能一次保存全部档位。输出为新动画 WebP，保存到当前素材目录，原文件不覆盖。回到主界面后再处理、校准和加入桌宠；剪辑不会自动替换桌宠。改了片段或档位后需重新生成，避免保存过时结果。

保留输入分辨率、透明通道和原帧时序，不统一成低清视频或固定帧率。裁剪切到帧中间时缩短该帧的显示时长；编码器可以合并连续相同画面，但总时长和画面顺序不变。未校准透明片段按底部居中补留白，已校准片段按记录的脚底对齐；不会拉伸人物。非透明原片画布不同，或混用透明和不透明素材时，会要求先统一处理。最终动作限60秒、3600个输入帧，兼容现有素材库。

文件体积不随片长单独决定：原视频 VP9 使用视频帧间压缩，重编码成逐帧无损 WebP 可能短片反而更大。Q95/Q90/Q85 使用颜色压缩与无损 alpha；Q 值不是清晰度百分比，也不承诺固定体积。全片未作改变的无损对比可直接复用原 WebP 压缩字节；重新导入已校准素材时，若画布、缩放、位置和稳定处理都未改变，也复用现有编码，避免压缩版再次膨胀为无损帧。另调大小或稳定参数时，仍需按原有无损母版流程重建。

下拉框改为统一的圆角、浅灰悬停、右侧箭头和当前项勾选样式，支持原有键盘操作；导出档位菜单支持同时勾选多项。

档位菜单和编辑窗口会提前显示各档预计体积：后台抽取当前选段开始、中间和末尾的连续画面，按实际输出画布和各档编码抽样计算，通常最多12帧、约64 MB的RGBA样本；不降低分辨率试算，也不使用固定压缩比例。预测以区间标为“抽样”，实际大小可能超出该区间。起止点、重复次数、顺序或素材变化后会更新；编辑期间可取消旧估算，不阻塞预览。完整复用的无损文件或已有同参数导出结果可直接给出已知大小。

生成后显示实测大小；大小摘要的提示可查看此前预计值和相对中值偏差。已生成结果按输入文件状态、校准信息、选段和编码档位缓存，换一段不会沿用旧预测。缓存位于本机状态目录，不上传用户素材。压缩时还校验透明画布标记，避免不透明矩形帧覆盖在透明底板上时被解码器误读成RGB。

拼接采用直接接续，不生成中间姿态、不自动补帧或添加淡出。前段末尾和后段开头的姿态、人物大小与脚底相近时更顺。音频不带入桌宠素材。生成、校验、保存都在后台执行，可取消；失败不修改原片或覆盖已有输出。

## 算法与接入行为

已处理的 WebP 剪辑携带不含私人路径的画布、脚底和参考身高信息；再次处理时沿用这些参数，不重复猜脸部大小，也不再次套用批量倍率。不同已校准画布拼接时按声明的脚底对齐。旧版播放文件由工作台从当前校准记录传入这些信息，原文件保留。

如果原视频本身缓慢放大或下沉，在“调大小 / 位置”中启用“修正缓慢放大 / 下沉”再生成。它沿全段采样可信头脸尺度和主体脚底，平滑修正慢漂移，保留肢体姿态、透明度和时长；预览与导出共用逐帧变换，不能把第一帧对齐当作全段稳定。样本不可靠会停止。默认不对其他动作启用此项；已烘焙的稳定结果不会重复矫正。该窗口也可选择是否参与随机动作，保留未剪辑原片作手动参考。

`media.py` 保留 VP9 alpha 解码、绿底拟合、U²-Net 支持区、去绿边及有限时序稳定；`cartoon.py` 用确认的白龙参考匹配眼睛与脸部比例，减少雨伞、灯笼及离散粒子对人物大小和脚底判断的干扰。`alignment.py` 共用预览和导出的变换；`webp_padding.py` 给原素材容器增加透明留白时保留压缩像素和逐帧时长。

透明边缘不是保证一次自动处理就完美：复杂头发、半透明衣物、同色道具和非均匀绿底需要逐段查看。原片已经裁掉的内容无法还原；源片碰边会记录，新增输出不允许再额外裁掉内容。加大画布不会创造源视频没有的高清细节。

默认保留原白龙全部动作和循环接缝，新增独立角色库并切换。安装前校验文件，使用进程锁、暂存、备份、正常退出请求和启动后运行记录核对；失败按事务回退。不会强行杀掉桌宠。内容相同且素材库、角色选择和设置已经一致时，重复加入不会重复编码或重启。改名可能影响动作识别，请保留源文件名；支持的素材后缀见 `updater.py`。

## 配置、模型与隐私

首次会自动定位本仓库，设置在本机生成的 `配置.json` 中保存；也可复制 `配置.example.json` 后编辑。Windows/macOS 路径分开存储，比例与手动调整可共享；换电脑后在设置中指定对应源码和素材目录。相对路径按配置文件所在目录解析。

原始视频、人物照片、模型权重、缓存、运行记录和配置不进 Git。缓存与回退位于桌宠本机数据目录下，输出位于界面选定目录。`models.json` 记录模型来源、固定下载地址和校验值；下载失败保留旧模型，不跳过 TLS 或哈希校验。模型与参考图分别遵循其来源授权，白龙角色来源见仓库 `NOTICE.md`。本工具中的 `白龙标准参考.png` 仅用于白龙比例校准；不会上传用户的真人参考图。

## 检查

在仓库根目录、已安装上述依赖的环境中执行：

```sh
python tools/check_material_workbench.py
```

入口按测试模块隔离进程及用户数据，验证容器透明像素/时长、道具校准、手动调整、参考面板、重复加入、失败回退、跨平台配置和模型下载完整性。模型下载测试使用本地构造字节，不联网。GitHub workflow 已加入 Windows/macOS 检查定义；是否实际执行取决于仓库 Actions 设置。

本目录保留 `media.Face` 作为旧真人处理算法代码，但白龙工作流使用 `CartoonFace`，不加载 YuNet 模型；真人素材和原真人配置不包含在此仓库中。
